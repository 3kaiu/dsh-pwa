## 整改（用户指示「逐项进行」，5 项全部实施并验证）

### 根因突破：暖机是**构造性必失败**，不是环境问题

给暖机加了「失败保留日志」之后，下一次冒烟留下的 `$RT_STATE/logs/warmup.log` 直接给出答案：

```
daemon: 更新进行中(install.lock 持有存活 pid),本轮不拉起 dsh   ← 重复 26 行
```

`install.sh` 全程持 `$RT_HOME/.install.lock`（安装互斥），而守护 `update_locked()`
（daemon.c:255）读同一把锁、见 pid 存活即判「更新进行中」并拒绝 spawn（daemon.c:296）。
暖机在 install.sh 内部起守护 → 必然撞锁 → dsh 一次都没被 fork → 必然超时。
**与机器快慢/网络/CI 无关。** 这也说明此前「暖机 3s 就绪、生成 1307 个缓存」的说法
无法复现：那些缓存来自日常 PWA 使用。

修法：暖机实例改用独立无锁临时 `RT_HOME`（`mktemp -d /tmp/dsh-warmup.XXXXXX`，
复制 `daemon`+`run.json`，置 `DSH_RT_NO_AUTO_UPDATE=1`），**`RT_STATE` 保持真实路径**
（`NODE_COMPILE_CACHE` 按 RT_STATE 算，daemon.c:348）；收尾清 `dsh.json`/`dsh.pid` 与临时目录。

### 5 项改动

   `$LOG_DIR/warmup.log` + CI `::warning`；收尾摘要如实点名三态。
2. `install.sh` 4c：缓存已热且 dsh 版本未变 → 免做（按版本判定，防升级后误跳）。

故「argv 里的路径」与「lsof 报的路径」不一致时，说明目录在进程启动后被移动过。

### 孤儿泄漏的修法（关键）

暖机**成功**分支才发 `/stop`，失败分支只 `kill "$WDPID"` —— 但 dsh 是 `setsid()`
出来的**独立进程组**（`daemon.c:339`），杀守护杀不到它，于是每次暖机失败都留一个
监听中的 dsh。修法两条：

1. `/stop` 提到两分支共用的位置，**且先读 `dsh.pid` 再发 `/stop`**
   —— 守护停止 dsh 时会 unlink 该文件，顺序反了就读不到。
2. 兜底：`kill -TERM -- "-$pid"`（负 PID 整组），1s 后仍活再 `-9`。

回归测试 `warmup-orphan.bats` 用**行锚点抽取真实 4c 代码块**（不是重写一份），
配一个「只 setsid 起子进程、不实现 HTTP」的桩守护 → 必然走失败分支。
**fail-before 实测**：修前 exit=1 且报 `orphan dsh survived the warmup cleanup (pid 66025)`；
修后 exit=0。含锚点漂移守护 + 反空转断言 `[ -s "$FIX/child.pid" ]`。
